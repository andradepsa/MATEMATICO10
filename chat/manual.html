Introduction

Chat K10 V18 is a decentralized communication platform that works without central servers. Unlike traditional chat apps (WhatsApp, Telegram, Discord), your messages never pass through a company database. You talk directly to other people (Peer-to-Peer) or through optional helper servers that you or your friends can run.

The entire application runs as a single HTML file — no installation, no account, no telemetry. Open it in any modern browser and you're ready to communicate privately.

Key Principles

🚫
No central databaseNobody stores your conversations. Data stays between peers only.
🔐
End-to-end encryption (AES-256-GCM)Only the recipient can read your messages — not even a server owner.
🌐
Runs in any browserNo installation required. Just open the HTML file and start chatting.
💾
Works offline / on a USB stickPerfect for emergencies, restricted networks, LAN parties, or air-gapped environments.
🔗
Share links, not heavy dataYouTube, radio, and most media are shared via URLs. Each user streams from the original source — the chat never carries video bytes.
ℹ️
Who is Chat K10 for? Friends who want private, uncensored conversations · Communities that don't trust corporate apps · Educational groups (Quiz Bot, Whiteboard) · Events, LAN parties, or situations with limited internet access.

Three Ways to Use Chat K10

The application operates in three distinct modes. Understanding them unlocks every feature.

MODE 01
Direct P2P
Two browsers connect directly via WebRTC. No server involved. Maximum privacy.
MODE 02
Server Relay
Connect through a K10 server. Works behind strict firewalls. Up to 200 users.
MODE 03
General Web (Hydra)
Messages flood the P2P mesh. No user limit. More peers = stronger network.
01

Mode 1 — User ↔ User (Direct P2P)

Two browsers establish a direct WebRTC connection. No server is involved at any point. The message travels directly from sender to recipient at the lowest possible latency.

✅ Best forPrivate one-on-one conversations, file transfers, video calls, DJ Radio (MP3 upload) ⚡ AdvantageFastest and most private — works even if all servers are offline ⚠️ LimitOnly two participants; may be blocked by strict firewalls or symmetric NAT ▶ How to startAdd the other person's Peer ID as a contact, then click to connect
02

Mode 2 — User ↔ Server ↔ User (Relay)

Everyone connects to a central server (ID ending with -CENTRAL). The server receives messages and retransmits them to all connected users. If linked to other servers (federation), messages also reach those servers and their users.

✅ Best forGroup chats, users behind strict firewalls/NAT, persistent rooms ⚡ AdvantageWorks on restricted networks; supports many people (up to 200 connections per server) ⚠️ LimitServer owner can see unencrypted messages — use Group E2EE to prevent this ▶ How to startOpen ServidorChatK10.html, copy the server ID, share with friends. They add it as a contact.
03

Mode 3 — General Web (Hydra / Infinite P2P)

When no contact is selected, you enter the General Web. Your message is broadcast using controlled flooding. Each user connects to up to 15 neighbors (or 50 in SuperNode mode). Every message carries a TTL counter (default 15) — each relay decrements it; when TTL reaches 0 the message is discarded. A recent-IDs cache prevents infinite loops.

✅ Best forPublic broadcasts, anonymous chatting, when a server is full (automatic migration) ⚡ AdvantageInfinite scalability — no user limit. More people = stronger network. No central point of failure. ⚠️ LimitMessages are public. Latency may increase due to multiple hops. ▶ How to startDeselect all contacts and type a message. The header shows GENERAL MODE ACTIVATED in green.
💡
Switching modes: Click a contact → P2P  ·  Add a -CENTRAL server ID → Relay  ·  Deselect all contacts → General Web. The General Mode Info button (next to the online counter) shows a full explanation pop-up.

Server Features

Open ServidorChatK10.html to become a server owner. Your computer will relay messages for other users. The server interface provides full control and real-time statistics.

🤝
Friendly Servers — Server Federation

A server can add another server (ID ending with -CENTRAL) as a contact. Once connected, the two servers form a federation. When User A sends a message: (1) Server A broadcasts to its own users → (2) Server A forwards to every federated server → (3) each federated server broadcasts to its users. The same TTL and anti-loop cache applies. Each server handles up to 200 users — federation allows thousands across multiple servers. Resilience: if one server goes down, others continue. Users never need to know about federation; it's completely transparent.

▶
In the server interface, type the other server's ID (must end with -CENTRAL) in the "Connect to another Server" field and click Connect.
📺
YouTube Live Chat Broadcasting

The server can mirror a YouTube Live chat to all connected users. They see a second tab — Chat YouTube — with the live comments embedded. Start: click "Start YT Chat" and paste the YouTube Live URL. Stop: click "Stop YT Chat".

Individual clients can also start and stop YouTube Live Chat independently (via Tools → Start YouTube Chat), sending the live comment tab to their contacts without needing the server.

🐉
Auto-Hydra Mode — Self-Scaling

When the server reaches 150 connected users, it automatically switches to Hydra mode: it sends a list of known peers to everyone, then disconnects. All users migrate to the General Web (P2P mesh) — the chat never stops. The hard cap is 200 connections; beyond that, new connections are rejected or migrated. This is how the network scales infinitely without crashing the server.

📊
Server Statistics (Real-Time)

Live dashboard shows: messages received / distributed · active connections · estimated Hydra Web size (P2P node count) · audit log with all connection events.

📻 Radios & Media — Detail

World Radios pull from radio-browser.info's database of 30,000+ stations. Type a country name, pick a station, preview it, then broadcast the stream URL to the room. Each user plays the audio directly from the radio server — no audio data passes through the chat.

▶️ YouTube — All Possibilities

YouTube is deeply integrated into Chat K10. There are five distinct ways to use it, all available to any user — no special permissions required.

💡
The chat never carries video bytes. Only the video ID (or playlist ID) and a sync timestamp travel through the P2P network. Each user's browser streams the content directly from YouTube's servers, keeping traffic minimal and copyright compliance intact.

1 · YouTube Radio — Any User Can Broadcast Any Live, Video or Playlist

Any connected user can act as a broadcaster at any time. This includes YouTube live streams — not just recorded videos. To start:

  1. Click Tools → YouTube Radio (or the YouTube Radio button).
  2. Paste any YouTube URL: a normal video, a live stream (youtube.com/live/… or watch?v=…), or a playlist (list=…).
  3. Click a number in the quick-grid (1–103) to use a saved favourite — or type the URL directly.
  4. All recipients automatically receive a radio-youtube-start message and a floating player opens on their screen, tuned to the same point in the stream.

When the broadcaster stops the transmission (Stop YouTube Radio), all players close automatically on every connected client.

2 · Synced Playback (startTime)

For recorded videos and playlists, the sender calculates a startTime a few seconds in the future and embeds it in the broadcast message. When that moment arrives every recipient starts playing simultaneously — eliminating the "who's ahead?" problem in watch parties. For live streams the player simply joins the live edge, so everyone watches the same live moment.

3 · Floating Player Controls

The YouTube player appears in a draggable, resizable floating window. Options available during playback:

  • Show / Hide Video — toggle to listen as audio-only (background music mode).
  • Video Size — Small (320 × 180 px) · Medium (560 × 315 px) · Large (854 × 480 px).
  • Individual volume control inside the YouTube iframe.

4 · Quick-Grid of Favourite Links (1–103)

The YouTube Radio panel shows a numbered grid from 1 to 103. Each slot can store a custom YouTube URL (video, live, or playlist):

  • Left-click a number to immediately broadcast that link to the room.
  • Right-click a number to edit / replace its saved URL.

Numbers with a saved link appear highlighted in blue; empty slots appear white. The grid makes switching between DJ sets, live channels, or playlists instant — no copy-paste required.

5 · YouTube Live Chat (Comments Tab)

Separate from the video stream, any user (or the server) can relay the comment section of a YouTube Live to everyone in the room. This opens a second tab — Chat YouTube — displaying the live comments via YouTube's official embed (youtube.com/live_chat?v=…). Two ways to start it:

  • Server: Click Start YT Chat in the server interface → paste the live URL → all connected clients receive the comments tab. Stop with Stop YT Chat.
  • Any client: Click Tools → Start YouTube Chat → paste the live URL → the comments tab propagates to all P2P contacts. Stop with Stop YouTube Chat.

The comments tab and the video stream (YouTube Radio) are independent — you can run both at the same time for a full watch-party experience: video playing in the floating window, live comments visible in the side tab.

▶
Quick-start for a live watch party: Open Tools → YouTube Radio → paste the live URL or click a grid number → the live video opens for everyone. Then open Tools → Start YouTube Chat with the same URL → the comments appear in a separate tab. Done.

📞 Voice & Video Calls — Detail

Encryption (E2EE)

Chat K10 uses AES-256-GCM encryption with PBKDF2 key derivation. Nobody except you and the recipient can read your messages — not even the server owner. Encryption must be activated manually and requires both parties to exchange secrets.

Step-by-Step to Activate Encryption

1
Click the 🔑 button in the message input bar
A modal window opens listing your online contacts.
2
Select the contact who is online and connected
Only currently online contacts appear as selectable.
3
Click "Send Secret Now"
Your browser generates a unique cryptographic secret and sends it directly via P2P — the server never sees it.
4
The other person must do the same for you
⚠️ Critical: encryption is bidirectional. They must also click the button and send their secret to you. Sending only yours is not enough.
5
Look for the lock icon — you're fully encrypted
Once both sides have exchanged secrets, a 🔒 appears next to the contact's name. All subsequent messages are E2EE.

Encryption Indicators

🔒
Full E2EE ActiveBoth sides exchanged secrets. All messages encrypted in both directions.
📤
Sending EncryptedYou sent your secret, but the other side hasn't replied yet. Your outbound messages are encrypted; inbound are not.
📥
Receiving EncryptedYou can read their encrypted messages, but you haven't sent your secret yet.
🔐
Group EncryptionGroup E2EE active on a server. Messages pass through fully encrypted — the server sees only ciphertext.

Group Encryption on Servers

If connected to a -CENTRAL server, you can activate group encryption. Prerequisite: you must have exchanged individual secrets with every participant first. Click the encryption button next to the server in the conversations list. A group secret is generated and sent to all contacts who already have E2EE with you. From then on, all messages through that server are encrypted — the server sees only gibberish. Users without the group secret see blank messages.

⚠️
New users joining later do not automatically receive the group secret. An existing participant must manually share it with them out-of-band.

Invite Links & Sharing

Peer IDs

Every user and every server has a unique Peer ID. Client IDs are 9 random characters (uppercase letters + digits, excluding look-alike characters such as I, L, O and 1 — e.g., A3BX7KQ2P). Server IDs must end with -CENTRAL (e.g., MyServer-CENTRAL). Your ID appears in the blue bar at the top — click Copy to share it.

Invite Links (Client Only)

Only the Chat K10 client (not the server) can generate invite links. Click Generate Invite Link. A complete URL is created containing your ID and the IDs of the first 15 users from your active connections list (your own ID always comes first, followed by up to 14 contacts — even if you are connected to more). When someone opens that link, they automatically connect to all listed IDs.

Security & Abuse Prevention

Chat K10 includes multiple protection layers against misuse, even if someone modifies the client code to attack the network.

Automatic Anti-Spam Measures

⏱️
Message rate limitingEach user must wait between messages based on network size: wait = max(1s, ⌊networkSize/1000⌋ × 1s) — minimum always 1 second; grows with the crowd (e.g. 2,000 users → 2s wait).
🚫
Three-strikes banAfter 3 spam violations, the offending peer is locally banned and the connection is closed.

Anti-Loop & TTL System

Every message carries a unique ID and a TTL (Time-To-Live) counter (default: 15). Each retransmission decrements TTL by 1. When TTL reaches 0, the message is discarded. Servers and clients maintain a cache of up to 10,000 recently seen message IDs to prevent duplicate processing.

Server Protections

🚦
Heartbeat monitoringClients must send a heartbeat every 30s. Idle for 45s → automatically removed.
🐉
Auto-Hydra at 150 connectionsPrevents server overload by migrating users to the P2P mesh automatically.
🔁
Exponential backoff reconnect (server)The server uses a circuit-breaker: exponential backoff up to max 20 attempts before giving up on a failed PeerJS connection. Clients use a separate backoff capped at 30s per retry with no hard attempt limit.
🚫
Blocks file transfers & large audioServer blocks file-start and file-chunk messages, and rejects audio >2 MB, to save bandwidth.
✅
Best practices for secure use:
• Always exchange E2EE secrets with your contacts (🔑 button)
• For server groups, activate group encryption after exchanging individual secrets
• Use the General Web (Hydra) for maximum resilience — no central point of failure
• If you suspect an attacker, manually remove their Peer ID from your contacts

FAQ & Troubleshooting

"I see a white screen for a few seconds when opening" —
Normal on first load — the browser is compiling React/JSX with Babel. Wait 3–7 seconds; a loading spinner appears. For faster startup, host the HTML file on a local web server instead of opening directly from disk.
"My friend cannot connect to me" —
Make sure both of you are online and have allowed microphone/camera permissions if needed. Try using a server (connect to a -CENTRAL server) — it helps with strict firewalls and symmetric NAT. If behind a very restrictive network, use General Web mode (deselect all contacts). Your message will find a path through the mesh.
"Encryption doesn't work" —
Both sides must exchange secrets. Just sending your secret is not enough — the other person must also click the 🔑 button and send their secret to you. Check the indicator next to the contact's name: 🔒 means fully active E2EE.
"The server is full / I got a migration message" —
The server reached its 150-user Auto-Hydra threshold. You were automatically moved to the General Web — this is normal and good; the network is scaling. You can keep chatting normally without any interruption.
"Quiz Bot questions appear in the wrong language" —
Change your language in the header dropdown. The next questions will be auto-translated via Google Translate. On very slow connections you might briefly see the original language before translation completes.
"What happens if I stop the Quiz Bot?" —
If you click "Stop Bot", the bot automatically transfers to the connected server (if any). The server continues sending questions without interruption from exactly where you left off. If no server is connected, the bot stops completely.
"My video call is laggy" —
Video calls depend on your upload speed. Switch to voice-only for a much lighter load. Use direct P2P mode (not through a server relay) for best performance. Quality controls are planned for a future version.
"I can't send files larger than 5 MB" —
5 MB is the limit for direct WebRTC file transfer. For larger files, use the Torrent Manager in the Tools menu — it supports files up to 500 MB via WebTorrent (only the magnet link travels through the chat).
"What is the difference between a Peer ID and an Invite Link?" —
Peer ID: A 9-character code (e.g., A3BX7KQ2P or MyServer-CENTRAL) that identifies you on the network. Share it manually by copying and pasting. Invite Link: A full URL generated only by the client. When someone clicks it, the chat opens and automatically connects to all listed peer IDs — convenient for inviting multiple people at once.
"How does the General Web have no user limit?" —
There is no central server. Each user connects to up to 15 others (50 in SuperNode mode). Messages hop from user to user up to 15 times (TTL). The network grows organically — more users make it stronger, not weaker. The 200-connection server limit only applies when you choose to use a relay server. The General Web is truly limitless.
