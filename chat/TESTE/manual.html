Introduction

Chat K10 V11 is a fully self-contained, decentralized communication platform. There is no separate server application. Everything — chat, relay hub, Quiz Bot, media tools, Monitor — all live inside a single ChatDesktop.HTML file. Open it in any modern browser and you are immediately part of the network.

Unlike traditional chat apps, your messages never pass through a company database. You talk directly to other people (Peer-to-Peer) or through relay hubs that emerge automatically from within the network itself — no dedicated server machine required. Starting with V79+, two P2P transport layers coexist: PeerJS (WebRTC fallback) and libp2p with GossipSub (P2P layer). From V10+, the app additionally integrates the open Matrix protocol for the General tab, Salinhas (Matrix rooms), and Groups — no additional account required to read; login is only needed to send messages.

Libp2p & Matrix Integration (V10+)

Chat K10 maintains a full libp2p stack for peer discovery, relay election, and direct P2P connections. From V10+, all group/room chat — the General tab, Salinhas, and Groups — now runs over the open Matrix protocol instead of a libp2p GossipSub general room. Both layers coexist and complement each other.

01

libp2p — P2P, Relay & Anchor Layer

Libp2p handles peer-to-peer connections, K10CentralShadow (relay hub election), K10GatewayShadow (gateway slots 0001–0005), and K10AnchorShadow (self-bootstrapping discovery without external servers). Voice/video calls, file transfers, torrents, and relay hubs all run on this layer.

✅ Used forP2P chat, relay hub, voice/video, file transfer, torrent, anchor node discovery.

Four Network Topologies

The routing architecture of Chat K10 operates across four distinct topological flows, now enhanced by automatic libp2p overlay networks. All four modes are available from within the same ChatDesktop.HTML file — no additional software required.

TOPOLOGY 01
User ↔ User
Direct P2P channel. No relay, zero intermediary latency.
TOPOLOGY 02
User ↔ Hub ↔ User
Star topology. A K10‑CENTRAL relay hub rebroadcasts messages to a group (PeerJS).
TOPOLOGY 03
Hub ↔ Federated Hubs ↔ Users
Tree topology. Multiple relay hubs link together; multiplies capacity immensely.
TOPOLOGY 04
General Mode (Hydra Mesh + GossipSub)
Controlled flooding via libp2p GossipSub. Everyone relays to everyone — no hub required.
01

User ↔ User (Direct P2P)

Two browsers establish a direct WebRTC connection. No relay in the middle. The message travels directly from sender to recipient over the shortest possible network path.

✅ Best forPrivate one-on-one conversations, voice/video calls, file transfers (PeerJS or libp2p private topics).
02

User ↔ Relay Hub ↔ User (Central Relay)

Everyone connects to one K10‑CENTRAL hub — a Chat K10 instance that was automatically elected as the group relay via K10CentralShadow. The hub rebroadcasts messages to all connected users. No separate server application is needed; the hub role is played by a regular Chat K10 client that wins the shadow election.

✅ Best forStable group chats, users behind strict firewalls or symmetric NATs, group encryption (E2EE).
03

Federated Hubs (Tree Topology)

Hubs link together by adding each other as contacts (-CENTRAL IDs). Messages propagate across all federated hubs automatically. Each hub uses its own K10GatewayShadow with dual‑server redundancy (mirror topology).

✅ Best forMassive audiences crossing the 200-user limit of a single hub.
04

General Mode (Hydra Mesh / GossipSub)

The Geral tab connects to public Matrix rooms (e.g., #conversa:matrix.org). Messages are stored and relayed by the Matrix homeserver network — a federated, open protocol. Users read without login; sending requires a Matrix account. The libp2p layer remains active in parallel for P2P/relay functionality.

✅ Best forOpen, federated public chat accessible to anyone, including guests with no account.
⚠️
In General Mode, every message is broadcast to the entire mesh. If you need private conversation with two people only, do not use General Mode — select the contact in the Private tab and activate E2EE (🔑).

Built-in Relay Layers

Chat K10 V11 does not require any separate server application. Two automatic layers provide discovery and redundancy:

✅
No extra files needed. All discovery logic, router mode, federation, mirror gateway, and anchor nodes are built into ChatDesktop.HTML.
👑
K10CentralShadow — Automatic K10‑CENTRAL Election

Every instance runs K10CentralShadow silently. The peer with the lowest peer ID among all known nodes automatically becomes the elected PeerJS hub. It registers K10‑HUB-V62 and answers central-discovery-request with the list of active gateways. If the elected peer disconnects, the next peer in order takes over immediately — zero user intervention.

🚏
K10GatewayShadow — Distributed Gateway + Dual‑Server

Each slot from K10-GATE-0001..0005 is filled by the first client that claims it (proactive election). The gateway manages groups of up to 50 users, sends peer‑lists, and performs mirroring: one gateway establishes a single WebRTC connection to another gateway, acting as a mirror for all groups that have ≥2 users. If the primary gateway fails, the mirror takes over automatically — true redundancy.

⚓
K10AnchorShadow — libp2p Anchor Nodes (V76+)

To make libp2p discovery work without any central server, up to 5 anchor nodes are elected automatically among browsers. Anchors announce their multiaddrs every 30s on the k10-anchors GossipSub topic. New peers dial those addresses and join the DHT. The TTL of an anchor is 90s; when a peer disconnects, the slot is freed and another peer takes over. No external bootstrap servers — the network bootstraps itself.

🤝
Hub Federation (Tree Topology & Mirror)

A hub can add another hub's -CENTRAL ID as a contact. Once connected, the two hubs form a federated tree. The mirroring mechanism ensures that if one hub goes down, its mirrored counterpart continues serving the group.

📺
YouTube Live Chat Broadcasting

Any Chat K10 instance (including a hub) can mirror a YouTube Live chat to all connected users. They see a second tab — Chat YouTube — with live comments. Start via Tools → Start YouTube Chat and paste the YouTube Live URL.

📊
Hub Statistics (Real-Time)

The hub interface inside Chat K10 shows a live dashboard: messages received / distributed · active connections · estimated Hydra Web size (P2P node count) · full audit log with all connection events.

📜

Audit Log & Network Health

The Audit Log (📜 Audit Log) is the "Pulse" of the Chat K10 network. It ensures complete transparency by logging real-time connectivity events, errors, and automated maintenance actions across the entire decentralized structure.

🔍 Automated Monitoring

Every Chat K10 instance maintains its own detailed Audit Log to detect "Ghost Connections" and verify synchronization. Every entry includes a precision timestamp and is color-coded by severity category.

✅ OKSuccessful handshakes, peer connections established.ℹ️ INFOHydra network structural changes (group split/merge) or auto-reconnection logs.⚠️ WARNGhost connection detected by GC, peer disconnected.❌ ERRORPeer ID already in use, remote peer not found.
GC

The "Ghost Connection" Garbage Collector

Chat K10 runs an active Garbage Collector (GC) every 5 seconds to ensure network stability. It monitors the connectionState of every remote peer; if a peer is failed, closed, or disconnected, the GC force-closes the socket and purges UI references.

🔒
Quiz Bot Lock System (4 rules enforced):

LOCK-1 — Exclusive owner: Only the peer who activated the Quiz Bot can stop it. The stop signal is compared against the original owner's peer ID, not the receiver's.

LOCK-2 — Non-owners never see the Stop button: Other users receive a static locked panel (a div), not a button element — so the stop action is completely absent from their DOM.

LOCK-3 — Auto-stop on owner disconnect + cooldown: When the owner disconnects, a 15-second timer starts. If the owner does not reconnect within that window, the quiz stops automatically and a cooldown of 3 minutes is enforced to prevent immediate restart by another peer.

LOCK-4 — Late-joiners receive the lock state: When a new peer connects after the quiz is already active, the handshake includes the current quiz state so they immediately see the locked panel.

Encryption (E2EE) — The Only Real Privacy

🚨
READ THIS FIRST: The "Private" tab only organises the interface — it does NOT encrypt your messages. Without encryption, your messages travel in plain text and can be read by other users or relay hub operators if routing goes wrong.

You must activate bilateral E2EE (🔑) to ensure that only the intended recipient can read the content. With encryption active (🔒 icon next to the contact), even if a message is misrouted, nobody else can decrypt it.

Step-by-Step to Activate Encryption

1
Click the 🔑 button in the message input bar
A modal window opens listing your online contacts.
2
Select the contact who is online and connected
Only currently online contacts appear as selectable.
3
Click "Send Secret Now"
Your browser generates a unique cryptographic secret and sends it directly via P2P — the relay hub never sees it.
4
The other person must do the same for you
⚠️ Critical: encryption is bidirectional. They must also click the button and send their secret to you. Sending only yours is not enough.
5
Look for the lock icon — you're fully encrypted
Once both sides have exchanged secrets, a 🔒 appears next to the contact's name. All subsequent messages are E2EE.
🔒
Full E2EE ActiveBoth sides exchanged secrets. All messages encrypted in both directions.
📤
Sending EncryptedYou sent your secret, but the other side hasn't replied yet. Your outbound messages are encrypted; inbound are not.
📥
Receiving EncryptedYou can read their encrypted messages, but you haven't sent your secret yet.
🔐
Group EncryptionGroup E2EE active on a relay hub channel. Messages pass through fully encrypted.
✅
With E2EE active (🔒), your conversation becomes truly private. Even if the network misroutes a packet, only you and the recipient hold the keys to decrypt it.

Group Encryption on Relay Hubs

If connected to a -CENTRAL hub, you can activate group encryption. Prerequisite: you must have exchanged individual secrets with every participant first. Click the encryption button next to the hub in the conversations list. A group secret is generated and sent to all contacts who already have E2EE with you.

Peer IDs & Sharing

⚠️
The "Generate Invite Link" button was removed in V10+. The automatic invite URL feature (which bundled your ID + 15 contacts into a shareable link) no longer exists in the interface. Sharing is now done manually using your Peer ID or the URL parameter below.

Peer IDs

Every user has a unique Peer ID. Client IDs are 9 random characters (e.g., A3BX7KQ2P). Hub IDs must end with -CENTRAL and are claimed automatically by the elected hub. Your Peer ID appears in the user info bar at the top — click Copy to copy it to the clipboard.

📋
To share your ID: copy it from the bar and paste it to anyone who wants to connect directly. They add it via the "Add Contact" field in the P2P tab.

Manual URL Parameters — Still Works

You can still pre-connect peers by appending the ?portas= parameter to the Chat K10 URL. Separate multiple IDs with commas. When the page loads, it automatically connects to all listed peer IDs.

https://your-host.com/ChatDesktop.HTML?portas=ID1,ID2,ID3,...

This is useful for creating a direct "join" link to a specific hub or group of peers — e.g., share the URL with your hub's -CENTRAL ID pre-filled so newcomers connect instantly.

System Architecture & P2P Physics

Chat K10 V11 uses three complementary layers: PeerJS WebRTC (fallback), libp2p GossipSub (P2P/relay/anchor), and the open Matrix protocol (General tab, Salinhas, Groups). The libp2p layer is bootstrapped via K10AnchorShadow, which elects up to 5 anchor nodes in the browser and keeps the DHT alive without any external server.

01

Matrix Federation & GossipSub (Dual Layer)

From V10+, public chat (General, Salinhas, Groups) runs over the Matrix federation — messages are stored and relayed by Matrix homeservers worldwide. For P2P mesh features (relay election, anchor discovery, direct connections), libp2p GossipSub remains fully active. Both layers run simultaneously in the same browser tab with no configuration needed.

02

Anchor Nodes & Discovery (V76+)

Without any central server, the network bootstraps itself: any peer that stays online for ≥2 minutes and has ≥2 active connections may become an anchor. Anchors publish their multiaddrs every 30s on the k10-anchors topic. Newcomers pick dialable addresses (preferring WebSocket or DNS) and connect directly. If an anchor disappears, the slot is re‑elected after 90s.

03

Dual‑Server Gateway Mirror (V70+)

A gateway (K10-GATE-XXXX) can establish a single WebRTC connection to another gateway, acting as a mirror for ALL groups that have ≥2 users. One connection mirrors dozens of groups. If the primary gateway fails, the mirror is promoted automatically — clients see zero interruption.

FAQ & Troubleshooting

"I'm in the Private tab, but other users receive my messages!" —
Cause: You haven't activated E2EE encryption. Without encryption (🔒), messages travel in plain text and network routing bugs can cause them to be delivered to unintended recipients — especially if you are connected to a relay hub or the Hydra mesh.

Solution: Activate bilateral encryption (🔑) with your intended contact. Once both sides have exchanged secrets (🔒 appears), the messages are encrypted end-to-end. Even if a packet is misrouted, no one else can decrypt it.
"Encryption doesn't work" —
Both sides must exchange secrets. Just sending your secret is not enough — the other person must also click the 🔑 button and send their secret to you. Check the indicator: 🔒 means fully active E2EE.
"What are Salinhas?" —
Salinhas are public Matrix rooms displayed in the Salinhas tab. Click Explorar Salinhas in the sidebar to browse a curated list. Click Entrar next to any room to add it to your conversations. You can also join any room by alias (e.g., #room:matrix.org). Reading is always free; login is needed to send.
"How do I join or create a Group?" —
Go to the Grupos tab and click + Entrar. Type a short name (e.g., meu-grupo) or a full Matrix alias (e.g., #alias:matrix.org), then press Entrar. If the room doesn't exist yet, Matrix creates it. Anyone who types the same alias joins the same room automatically — no invite link required.
"Do I need a Matrix account?" —
No account needed to read. All Matrix rooms in Chat K10 are publicly readable. You only need to log in when you want to send a message. The login modal appears automatically. You can sign in with Google, GitHub (via SSO), or a Matrix username + password. No account? Register free at app.element.io.
"What are Anchor Nodes?" —
Anchor nodes are elected browsers that help new peers discover the libp2p network. No central bootstrap servers are needed. Up to 5 anchors exist at any time; they announce multiaddrs via the k10-anchors topic. If an anchor disconnects, a new one is elected automatically.
"What is the General (Geral) tab?" —
The Geral tab connects to the public Matrix room #conversa:matrix.org (and other curated rooms). It replaces the previous libp2p GossipSub "Oficial Group". Anyone can read without an account. To send messages, click the input and complete the Matrix login (Google SSO, GitHub SSO, or username/password).
"What happens if the gateway mirror fails?" —
Gateways keep a mirror connection to another gateway. If the primary gateway stops responding, the mirror is promoted automatically within a few seconds. Clients connected to the mirror see no interruption. The network self‑heals.
"How do I see dual‑server redundancy?" —
Open the Monitor Pro V9 (Tools → K10 Monitor). It shows for each group whether it has a primary (K10-AAAA-1) and secondary (K10-AAAA-2) server, and highlights mirror relationships.
"Quiz Bot questions appear in the wrong language" —
Change your language in the header dropdown. The next questions will be auto-translated via Google Translate.
"What happens if I stop the Quiz Bot?" —
Only the user who started the Quiz Bot (the owner) can stop it. When the owner clicks "Stop Bot", the quiz ends completely for all users — there is no external server to hand off to. If the owner disconnects, a 15-second grace period begins; if they don't reconnect, the quiz stops automatically and a 3‑minute cooldown is applied.
"My video call is laggy" —
Video calls depend on your upload speed. Switch to voice-only for a much lighter load. Use direct P2P mode for best performance.
"Do I need to run a separate server application?" —
No. Chat K10 V11 is fully self-contained. The relay hub role is assumed automatically (shadow election), anchor nodes are elected, and mirror gateways are established — all inside the browser.
